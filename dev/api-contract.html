公开接口契约¶

本库从定义模块导入类型与函数，终端操作使用安装后的 bazi 命令。例如：

from datetime import datetime
from bazi.bazi import Bazi
from bazi.bazi_chart import BaziChart
from bazi.defines import Tiangan
from bazi.school import BaziConfig

chart = BaziChart(Bazi.create(datetime(2000, 1, 1, 12), 'male', BaziConfig()))
assert chart.bazi.day_master in Tiangan

版本历史、旧新调用对照和升级条件见发布与迁移。本页只说明当前接口。

支持范围与导入路径¶

完整名称、类成员、字段、枚举别名、继承关系及规范定义路径登记在 tests/api_contract.py，供测试和参考文档共同使用。 PUBLIC_NAMES 登记定义模块的自有名称和既有包入口；REEXPORTS、ALIASES 区分重导出与别名。 DECLARED_MEMBERS 包含方法、属性、类型别名和字段；继承关系另由 BASES 登记。

  • 包的 __all__ 不是公开 API 全集；bazi.data_types 等定义模块同样可直接导入。

  • 领域枚举的中文与拉丁成员别名共用值；中文类型别名也保留，如 天干 与 Tiangan。

  • 第三方模块在源码中的偶然导入不是本库提供的 API。普通模块的依赖导入不自动成为规范重导出。

  • 下划线名字及 _validation 是包内约定，不承诺包外调用；共享接口的归属见 tests/data/internal_interfaces.json。

  • ContextResult 的 dataclass 构造函数及 dataclasses.replace 使用公开输入参数 _bazi。 读取结果时用 bazi 属性，每次取得独立深拷贝；输入参数与属性用不同名称区分。

  • 命盘流运统一用 TransitChart.at_year、at_month、at_date、at_moment 查询；bazi.transits 提供流运种类 TransitKind 和结果 TransitSet，数据库类仅供包内使用。

  • STATIC_MODULES 单独标记离线编码／生成工具与导入即读取数据表的后端实现。 离线工具按源码入口查阅，不是安装 CLI；检查清单不执行下载、生成或数据表加载。

  • 清单记录公开面，不决定运行时导出；运行时签名和类型以定义模块为准。

可接受的字符串输入¶

Bazi.create 的性别字符串只接受 男、女、male、female（拉丁大小写不敏感）， 也可直接传 BaziGender。枚举中的 乾、坤、阳、阴、YANG、YIN 不是性别字符串入口。

BaziConfig 构造函数接收声明类型；需要字符串解析时使用 BaziConfig.from_values。 精度支持 分／分钟／时／小时／天／日 和 m／min／minute／h／hour／d／day，拉丁大小写不敏感。 后端与大运年份规则分别由 CalendarBackend.from_str、DayunYearRule.from_str 解释成员名或值； 流派档案须传 BaziSchool，不接受字符串。性别、精度、后端各有自己的字符串写法，互不通用。

关系与附加查询¶

关系位置、通根与透干¶

TransitAnalysis.all_relations(transits) 返回 RelationPositionDiscovery，即地支关系到 tuple[frozenset[RelationParticipant], ...] 的冻结映射。参与者字段为 position: Zhu | TransitKind 和 ganzhi: Ganzhi；每个组合跨原局与所选流运两组。查询按本盘流派调用 discover_mutual_ganzhis， 保留其组合与顺序，只将序号改为位置；同干支不同位置不合并。

通根与透干从 bazi.analyzer.facts 查询：

  • tonggen(chart, target, transits=None, *, condition=TianganMatch.SAME_WUXING) 返回 tuple[TianganOccurrence, ...]，记录匹配的实际藏干。

  • tougan(chart, target, transits=None, *, condition) 没有默认条件；省略条件抛 TypeError。 target 先按同干定位实际藏干，再按显式条件与明干匹配，返回 tuple[TouganHit, ...]。

  • 两个函数的条件均为 TianganMatch.SAME_TIANGAN 或 SAME_WUXING。 不传流运只查原局；传入后两端均可来自原局或流运，保留同柱与重复干支位置。 位置按年、月、日、时，再按 TransitSet.items 的固定次序排列。通根在每个位置按 BaziRules.HIDDEN_TIANGANS 表顺序返回；透干按藏干位置优先、明干位置次序返回。没有匹配返回空元组。

TianganOccurrence(position, ganzhi, stem) 是冻结值。直接构造时，位置为 Zhu | TransitKind， stem 必须是该干支的明干或藏干。TouganHit(hidden, visible) 的两端均为 TianganOccurrence： hidden.stem 须属 hidden.ganzhi 的藏干，visible.stem 须等于 visible.ganzhi.tiangan； 不强制两端同干，结果中的明藏角色由字段指定。 上述查询与构造入口的错型抛 TypeError，构造值的干支与明藏角色不符抛 ValueError；普通运行与 -O 一致。 原局位置、流运种类与明藏两端实际值的示例见关系与流运指南。

月令五行状态与神煞名称¶

chart.wuxing_states 是 frozendict[Wuxing, WuxingState]，按原局出生月令给出五行各自的旺、相、休、囚、死状态。 五种状态各出现一次，WuxingState 及中文别名 五行状态 从 bazi.defines 重导出。 季月取法由 BaziSchool.tuwang_def 决定，该字段参与配置相等与哈希：

  • 默认 WHOLE_MONTH 将整个季月作为土旺，是本库的简化取法。

  • AFTER_TWELVE_DAYS 从开月节后十二日起取土旺，BEFORE_EIGHTEEN_DAYS 从下一四立前十八日起取土旺； 两种分段取法在阈值之前均按季节本令。

分段按连续 24 小时计日，比较阈值时使用出生精度、相等归新及地点钟政策；HKO 只作日期级比较。 完整比较步骤与用法见配置指南。

relationship.SHENSHA_LABELS（22 项）与 WHOLE_PILLAR_SHENSHA_LABELS（魁罡、天赦两项） 是公开冻结名称表，CLI 也使用这两张表。

六甲旬空¶

shensha_utils.xunkong(ganzhi) 返回该旬二支冻结集，kongwang(anchor_ganzhi, target_dizhi) 返回 目标支是否命中。错误外层或内部干支字段类型抛 TypeError，阴阳不配锚抛 ValueError，在 python -O 下同样检查；不改变 Ganzhi 自身的构造域。目标不附加天干、纳音或冲合条件。

BaziSchool.kongwang_anchor 默认 Anchor.DAY，支持 YEAR、YEAR_AND_DAY。 AtBirthAnalysis.kongwang 与 TransitAnalysis.kongwang(transits) 返回 tuple[KongwangResult, ...]， 逐锚记录 anchor（Zhu.年／Zhu.日）、ganzhi、由锚计算的 xunkong 和 hits。 KongwangHit(position, ganzhi) 的 position 为原局柱位 Zhu 或流运种类 TransitKind；ganzhi 保留完整目标。 无命中也返回该锚二支，双锚同值与重复目标位置不合并。原局排除锚自身柱，流运只从本命锚单向查询。 详情命中投影为地支集合，等于 shensha['kongwang']。不删除支、不改其他关系，不实现解释性取消或吉凶判断。

胎元与命宫附加查询¶

chart.taiyuan 与 chart.minggong 是无参缓存属性，返回不可变的 Ganzhi，只在首次访问时计算。 计算口径和可运行示例见集成指南；字段说明以 BaziChart.taiyuan／minggong 的 docstring 为准。时支固定取本盘时柱， DAY 也保留输入小时，地点盘取真太阳钟，换日设置（day_rollover）不改变时支。

命宫以中气判断月序是否进一，比较时按本盘出生精度处理，相等归新： DAY 比日期，HOUR 比日期及时辰起点，MINUTE 比日期及分钟起点； 地点盘先把边界换到与出生相同的真太阳钟。HKO 只支持 DAY，零点仅为占位，不是真实交节时刻。 时间政策是本库执行口径，不冒称古籍规定；300 日胎元和其他命宫月界仅存知识候选，未编码。

纯函数从 bazi.utils.bazi_utils 导入：taiyuan(month_pillar) 先检查外层 Ganzhi，再检查 tiangan／dizhi 字段类型，错型立即抛 TypeError；通过后检查是否属于合法六十甲子， 阴阳不配的组合抛 ValueError。minggong(year_tiangan, month_dizhi, hour_dizhi) 逐参接收 Tiangan、已调整的有效命宫月支 Dizhi、本盘时支 Dizhi，非相应枚举抛 TypeError。 普通运行与 python -O 下的校验行为相同；Ganzhi 构造器本身仍接受全部 10×12 个干支组合。

两值是四柱之外的单独查询结果，不扩展 BaziData 或柱位，不改变 school 和命盘身份。 它们不出现在 basic_text 等命盘文本中，不参与五行、十神、神煞、关系或流运分析。 读取它们不使任何解释条目的前提自动成立。

返回值、拷贝与相等性¶

共享与输入¶

  • 查询结果和规则集合使用 tuple、frozenset、frozendict 等不可变结构； frozendict 只冻结映射本身，不深拷贝其中的值。具体接口的可变边界仍看其类型与说明。

  • 命盘隔离传入的 Bazi，chart.bazi 每次返回独立深拷贝；不把 Python 属性只读等同于所有对象都深冻结。

  • Bazi 按值比较；BaziChart 按对象身份比较。两个命盘的 bazi 值可以相等，命盘对象本身仍不相等。 知识库按内容及顺序比较，ContextResult 按其值字段比较。

  • ContextResult 是 frozen dataclass；构造参数 _bazi: Bazi 验证后深拷贝，公开 bazi 属性每次返回独立深拷贝。 构造及 replace 使用 _bazi。相等／哈希使用 Bazi 的完整身份，包含性别、完整配置， 地点盘另含精确瞬间、固定民用偏移及经度。修改输入或属性返回的副本不改变已有结果。 ContextResult.render() 直接读取领域值，不重新排盘；直接构造只检查结构自洽，不认证输入、观察、证据之间的事实一致性。

  • 求值显式传入的 KnowledgeBase 被共享；未传时每次独立加载编辑源。已有结果不随源文件修改而变化。

  • 每次访问 chart.dayun、chart.liunian 都获得新生成器。保存到变量的有限生成器会耗尽； 流年生成器可无限延续，不要直接对它调用 tuple／list。chart.xiaoyun 是缓存元组，可重复遍历。

农历年信息¶

LunarYearInfo 定义在 bazi.calendar.dates，calendar.hko_data、calendar.hko_data.decoder、 calendar.celestial_data.loader 三条路径重导出同一类型，__module__ 指向 bazi.calendar.dates。 其 first_solar_day、leap、leap_month、days_counts、ganzhi 字段保留字典／可变列表行为，查询返回独立副本。

内存结果与重算¶

命盘和前提判别结果没有保存恢复接口，知识库也不导出快照，不提供替代记录格式。 需要当前结论时，用原出生输入与完整配置重新排盘、求值；本库不从历史记录猜补配置或重建当时结果。

对象摘要、报错指路与文本展示¶

  • 不支持 from bazi import Bazi。import bazi; bazi.Bazi 的 AttributeError 会指出定义模块； from bazi import Bazi 由解释器报 ImportError，不带这条指路。

  • dir(bazi) 列出 __all__ 声明的全部子模块，以及 chart_text、cli，包括尚未导入的按需子模块；dir() 本身不触发导入。 chart_text、cli 不进 __all__，但同样按需导入。

  • Bazi、BaziChart、TransitChart、RelationshipAnalyzer、AtBirthAnalysis、TransitAnalysis 的 repr 是一行摘要：出生时刻、性别、四柱，配置不是默认值或是地点盘时再附加对应部分；后五个对象以所持命盘的摘要为主体。 摘要大小与命盘数据无关，不计算流运或其他派生值。它只服务交互探索与调试，格式不属于兼容承诺， 不是记录格式，也不应被程序解析。

  • 接收命盘的公开入口（TransitChart、三个分析类、spouse_evidence、evaluate_context、 bazi.chart_text 的函数）在收到非 BaziChart 时立即抛 TypeError；调用方须传真正的 BaziChart，不接受只具有同名属性的对象。

  • 类型错误消息保持 Expected X, got <type> 开头，对常见误用在其后以分号追加指路，如 Expected BaziChart, got <class 'bazi.bazi.Bazi'>; wrap it with BaziChart(bazi)。 异常类型与开头不变；要判断错误种类，匹配开头，不要匹配全文。

  • bazi.chart_text 把命盘排成纯文本，不写文件，不依赖终端着色库，固定输入的输出可重放： basic_text（日元、出生时刻，四柱及其十神、阴阳五行、藏干、纳音、十二长生；地点盘另列民用、真太阳与节气表出生时刻）、transit_text（节、交运、大运、小运、流年； 流年无限延续，由 dayun_count、liunian_count 限定，默认 10 与 100）、chart_text（两者相接）。 出生后没有大运起于历法支持范围内时，transit_text 与 chart_text 抛 ValueError，与 BaziChart.xiaoyun 一致；basic_text 不受影响。 TextStyle 的两个钩子返回值原样放进文本，不做检查，默认原样输出；版式由调用方负责。排版随版本调整时在发布说明中说明。

观察请求与结果对象¶

位置、观察与坐标¶

  • bazi.defines.Zhu（中文类别名 柱）按年、月、日、时排列，成员为 NIAN/YUE/RI/SHI 与 年/月/日/时。 TianganLayer（天干层次）成员为 MINGGAN/CANGGAN 与 明干/藏干。两个类都从 bazi.defines 重导出； 定义模块分别是 defines.zhu 和 defines.tiangan。原局柱序与中文标签取自 Zhu。

  • KongwangHit(position, ganzhi) 和 StarAppearance 的 position 类型为 Zhu | TransitKind。 StarAppearance(position, ganzhi, layer, stem) 的 layer 用 TianganLayer；构造时检查明干与干支一致、藏干属于地支。 KongwangResult.anchor 只接受年、日，类型注解同时列出中文与拼音拼写；月、时在类型检查和运行时均拒绝。 配置 Anchor.YEAR_AND_DAY 仍是多锚选择策略，不是柱位。

  • ChartOccurrence(position, ganzhi, layer, stem, shishen) 的 position 为 Zhu | LiunianPosition； 后者保存具体 ganzhi_year。原局 index 为 0–3，流年为 4。 另一类型 bazi.utils.dizhi_utils.GanzhiOccurrence 用于关系查询组合，index 是调用方输入序列中的位置，不受四柱限制。

  • evaluate_context(..., observation=...) 显式选择观察请求。NatalObservation() 供全部判据共用； LiunianObservation(ganzhi_year=None) 用于原局加单流年，TransitObservation(kinds, coordinate=None) 用于婚恋结构岁运查询。 ScopeName 按 natal、natal_and_liunian、natal_and_transits 排序。

枚举字段的读取与穷尽分支¶

KongwangResult.anchor、StarAppearance.layer、ChartOccurrence.layer 使用不继承 str 的枚举。 判断用成员，如 result.anchor is Zhu.年、appearance.layer is TianganLayer.明干； 与 'year'、'visible' 等字符串比较、作 in 判断或关键字类模式匹配不会命中，且不一定报错。 当前仓级 mypy 参数不保证发现这种字符串比较。 打印 Zhu／TianganLayer 用 str(value) 取得中文值，打印 TransitKind 用 .value。 位置／明藏层显示使用枚举中文值，如 natal.月、藏干；scope、origin、kind 使用各自的标签。

运行时中文／拼音别名是同一成员，当前钉版 mypy 却将它们作为不同的 Literal 处理。 对 anchor 做穷尽缩窄时，年、日两个分支须各覆盖两种拼写，保留 assert_never 及月／时的类型拒绝。 完整示例与类型检查说明见集成指南。

命令行¶

console_scripts 中只有命令 bazi，对应 bazi.cli:main；不提供 python -m bazi 或根目录兼容脚本。 五个任务的用途、参数示例与输出路径见命令行指南。本节列输入、失败与文件写入的约定。

demo、relationship、chart 默认随机生成，打印种子，可用 --seed 整数 重放。 固定 chart 输入须同时给 --birth-time、--gender，不能与 --seed 或大于 1 的 --count 组合。 地点与时区输入沿用库的时间口径。 knowledge --list-values topic 对应 filter_values('topic')，match 与 match 判据ID 对应 criteria() 与 criterion(id)；CLI 不提供名称精确匹配或关键词检索参数。 knowledge 默认查询为空且同一知识库、同一过滤条件有参考条目时，提示 --include-reference-only， 不自动展示参考条目；真空结果不提示，已有默认输出或已显式包含参考条目也不追加提示。

bazi.cli.main(argv=None) 的 argv 列表不含程序名，None 表示读取 sys.argv[1:]； 非列表或包含非字符串成员时抛 TypeError。裸调用与 --help 只打印帮助并返回 0，不写文件。 未知任务／选项、缺项或非法输入由 argparse 以退出码 2 报错；普通运行与优化模式保持相同的立即失败行为。

目录的年月字段为 ganzhi_year／ganzhi_month，对应 CLI flags 为 --ganzhi-year／--gz-month。 缺项／多余项错误使用完整字段名，如 Missing coordinate field for at_year: ganzhi_year 和 Unexpected coordinate field for at_year: ganzhi_month，这些边界错误也以退出码 2 报错。

两个写文件的任务遵守以下约定：

  • chart 只有显式传 --output-dir 才写文件，文件名为 interpretation_examples/{序号}.txt。

  • knowledge --export-knowledge-base 默认使用调用目录下的 output_data/knowledge_base/； --output-dir out 改为 out/knowledge_base/。默认路径不取安装位置。

  • TXT 剥除终端颜色码。同名导出目标会覆盖，其他文件保留；包内或自定义知识编辑源拒绝覆盖， 指向该源的符号链接和硬链接也在保护范围内。

  • 两个任务独立检查各自目标，不提供跨命令冲突预检或整体回滚。

知识查询与编辑¶

名称、关键词与过滤值发现¶

KnowledgeBase.find_objects、search 的调用示例见知识库指南， 完整签名与字段说明见定义模块的 API 参考。两个入口的输入检查相同：空或全空白字符串抛 ValueError， 错型抛 TypeError，有效字符串的两侧空白不会被剥除。匹配方式与顺序分别为：

入口

匹配与返回顺序

find_objects(name)

精确匹配对象名称，重名全部返回，无匹配返回 ()；按对象注册顺序排列。中文名称不是唯一 ID，不作模糊匹配或大小写转换。

search(keyword, ...)

先应用 query 的七维交集与参考条目政策，再作 Unicode casefold 字面子串匹配；按语料顺序排列，默认排除仅供参考的条目。

关键词检索覆盖条目正文、前提、署名、主题、口径、例外、限度及角色对象名称， 不搜对象／条目 ID、来源全文或情境标签，不解释正则，也不判断命盘适用性。 来源全文从 sources 读取，关联条目用 query(source_id=...) 查询。

filter_values(dimension) 给出七维合法值全集，按 Unicode 字符串序排列：

  • 维度为 object_id、context_id、source_id、topic、viewpoint、applicability、time_scope， 不包含布尔选项 include_reference_only；未知维度抛 ValueError。

  • 目录包括仅参考条目独有值、未引用的注册对象／来源／情境及其时间范围；空库的 applicability 也有三个合法值。

  • query 与该目录共用合法值定义，但合法值不保证默认输出有命中。

判据目录¶

context_matching.criteria() 返回 frozendict[str, CriterionInfo]，criterion(id) 返回单项； 未知 ID 抛 ValueError，错型抛 TypeError。两者不加载知识库、不创建命盘，也不执行判别。 目录值冻结，直接构造 CriterionInfo 只校验值的形状，不将自填的 definition 当作已注册定义或据此派生结论； 需要已注册定义时使用这两个查询入口。

判据与国印查询均按稳定条目 ID 关联，不比较知识正文或来源的内容摘要。自定义库负责保持同 ID 的领域含义， 相同 ID 本身不能证明语义相同，目录也不认证条文真伪或现实适用性。

目录信息

含义

criterion_id、definition、observation_keys

稳定标识、现有判据定义及实际观察键。

analysis_kind、observation_types、scopes

分析类别，以及由它派生的可接受观察请求类与合法范围；没有隐式范围默认值。

required_inputs、optional_inputs、scope_inputs

求值入口的必填／可选参数及各范围取得完整观察所需的额外输入；关系范围按 coordinate、kinds 排序。

transit_entries、transit_kinds

婚恋结构观察的坐标入口、必填字段及种类上限；不保证某盘实际可取得。单流年观察不接 TransitCoordinate。

unknown_conditions

缺所需年份／坐标或流运不可用等导致 UNKNOWN 的条件；范围完整性先于性别门槛与事实判别。关系流运范围的 kinds=() 在构造时抛 ValueError，不产生 UNKNOWN。

entry_role

premise 判关联条目的完整显式前提；condition 只判局部事实，不认定条目全文前提已成立。空参考元组也由此区分。

required_gender、claim_genders

分别限制判据和关联条目的性别；具体效果见下文。

claim_ids

按判据声明序排列的条目 ID；自定义库不保证有这些条目。

只有 editorial.guansha_coexistence_female.v1 的 required_gender 为女命；范围完整时， 男命得到 NOT_SATISFIED/female_gate_false。普通官杀并见判据没有此门槛，两者都保留 female 观察键。 只向男命返回的两条婚恋条目由 claim_genders 限制：女命不返回这些关联条目，不改变事实判别。

ContextResult.reference_ids 从判据的 claim_ids 依次选取条目 ID，跳过以下三种情况：

  • 传入的知识库中没有该条目；

  • include_reference_only=False，而该条目的 show_by_default=False；

  • 该条目要求的性别与输入命盘不符。

返回的 ID 保留声明顺序和重复，不另行去重。include_reference_only=True 只放开参考条目的展示筛选， 仍须通过存在性与性别检查。没有返回参考 ID 时，判据仍可为 SATISFIED；前提满足不改变条目的默认展示资格。 状态只在 CriterionResult 上，条目没有 UNKNOWN 或识别状态；编辑正文、引文和来源说明不改变判据结果。 目录使用示例见知识库指南。

知识编辑源与文本边界¶

KnowledgeBase.load(Path | None) 每次读取并校验当前编辑源；省略路径读取随库 knowledge_data.json。 已有内存对象不随文件编辑变化。编辑源须含 schema_version 及 objects、contexts、sources、entries 四份注册表； 版本只接受精确整数 3，拒绝 bool、浮点数、字符串、容器、旧版与未知版，不自动迁移。 重复键、字段差异、断引用、不合法状态及无法按 UTF-8 编码的孤立代理项均拒绝，不修复原文。 非整数版本的 ValueError 仅显示类型，不展开未知容器。类型错误抛 TypeError，值或引用错误抛 ValueError； JSON 解析错误保留 JSONDecodeError 的原文与位置，实际解析递归失败转为 ValueError，不设固定深度上限。

字符串键在解析时检查 UTF-8，值使用显式栈遍历，不对整树重新编码。中文、非 BMP 字符、合法 JSON 代理对转义及字面的反斜杠文字保留。 知识和前提文字渲染同样检查 UTF-8，包括直接构造对象和展示参数；普通文字查询不因此收紧。 条目按稳定 ID 关联，编辑源版本不是条文真伪的认证。

KnowledgeEntry.show_by_default 只接受确切 bool；0、1、字符串和 None 均抛 TypeError。 该字段只控制默认展示，不认证知识正确或适用于当前命盘。

国印条目查询¶

bazi.knowledge.guoyin_entry(knowledge, definition) 接受 ShenshaRules.GuoyinDef，返回传入库的对应条目； guoyin_def(knowledge, claim_id) 返回对应定义，已注册但没有国印关联时返回 None。 所需条目缺失、ID 未注册或为空白时抛 ValueError，参数错型抛 TypeError；普通与 -O 一致。 来源由 entry.sources 查阅，关联不改变条目内容、来源状态或默认展示。
