Note:

  • premise 判关联条目的完整前提，condition 只判局部事实，不能据此认定条目全文前提成立。

class bazi.context_matching.ContextResult(observation, criterion, evidence, reference_ids, _bazi, knowledge)[源代码]¶

保存观察请求、判别、证据及知识条目结果。

构造参数 _bazi 接收 Bazi 输入，验证后保存独立深拷贝；bazi 属性每次返回独立深拷贝。 输入的完整身份参与相等与哈希，knowledge 复用传入的已验证 KnowledgeBase。 render() 直接读取领域值，不重新排盘或重建知识对象。

Note:

  • evidence 保存逐柱明藏出现或婚恋结构证据；reference_ids 保存参考条目 ID。 已注册判据的 entry_role 区分完整前提与条件参考，空元组也保留该区别。 构造期检查判据支持的观察类型、证据形状及条目 ID 是否存在于知识库。

  • 直接构造保留 reference_ids 的顺序和重复，不要求 ID 属于判据声明的 claims； 正常求值则按声明序经过缺条目、默认展示与性别筛选，不去重。

  • 婚恋结构结果另核范围与取得集合的自洽：原局不能带已取得岁运，取得种类不能超出请求； 岁运范围完整时须有查询坐标并取得全部所求种类，关系证据序号不得超出本次查询序列。

  • 不重算或认证命盘、判别、证据真伪，也不认证输入与证据干支的一致性； 原局／单流年结果不认证手填证据年份与请求年份是否配对。

bazi.context_matching.evaluate_context(chart, *, criterion_id, observation, knowledge=None, include_reference_only=False)[源代码]¶

检查选定范围是否满足已注册判据，返回判别、观察、证据及参考条目 ID。

Note:

  • NatalObservation 供所有判据共用；LiunianObservation 用于原局加单流年观察， TransitObservation 用于婚恋结构的多种岁运查询。不支持的观察种类抛 ValueError。

  • 官杀两条判据判别关联条目的完整前提。其余判据只判可计算事实：婚恋两条判结构，丁火、 庚金两条判日主，偏印、枭印两条判十神是否出现。身弱、有制有化、喜用、夺食、「有用／ 喜忌／成格」等完整理论条件留在知识文本，不为它们新增 UNKNOWN，也不认证其已满足； 所需流年缺失或不可查询时返回 UNKNOWN。

  • 参考条目须显式设置 include_reference_only=True。条件判据的关联条目只是条件参考， 与事实判别的状态无关；只向男命返回的关联条目对女命一律不关联，静态查阅不受限。

  • 未传 knowledge 时，每次独立加载默认来源，已保存的修改在后续加载时可见； 传入知识库则直接复用。已有知识库和结果保留原内容，共享调用须显式重载才能取得更新。

  • 观察原局年、月、时明干与四支全部实际藏干；请求流年时加入该流年明干与藏干。 不观察日主明干，但等于日主的藏干仍分类为比肩；藏干百分比不作权重，重复位置保留。 不另加力量／次数阈值、相邻、去留或有效制化条件。

  • 范围完整性优先于女命条件与事实判别：男命缺必需年份仍为 UNKNOWN / missing_transit_coordinate。 婚恋范围缺查询坐标为 UNKNOWN / missing_transit_coordinate；入口不可查询或所求种类 部分缺失为 UNKNOWN / transit_unavailable，已取得种类的证据照常保留。 SATISFIED / NOT_SATISFIED 只描述完整的显式前提，不证明现实事件成立。

  • 关联按稳定 claim ID，不比较文字或来源摘要；自定义库负责同 ID 的领域含义。 编辑正文、引文或来源说明不改变判据状态，也不使参考条目变为 UNKNOWN。

  • reference_ids 按判据声明序返回，省略缺失或被展示／性别门槛过滤的条目； 前提满足不授予默认展示资格。

Return: (ContextResult) 判据结果、逐柱观察或结构证据、参考条目 ID， 以及 Bazi 输入的独立副本和本次使用的 KnowledgeBase 对象。
