规则、知识与出处的覆盖¶

能计算一条规则、能查到解释文字、能追溯该条规则的出处，是三件不同的事。本页对账现有实现与知识目录，并用国印两读说明如何把它们连起来；不增加规则、查询接口或来源见证。

读表口径¶

  • 实现以规则表、定义枚举、计算入口与配置字段为准，不能从已有知识对象反推全部计算能力。

  • 知识关联指现有对象、条目和来源 ID。文字提到某个词，不等于已经有该规则的专门对象或结构化关联。

  • 源码出处包括规则旁的注释和定义 docstring。本页只记录这些说明的位置与支持边界，没有重新核验其外部古籍或天文数据。

  • repository_attributed 是本仓署名，witnessed 是已核原文出处，二者不互换；默认展示由 show_by_default 另管。状态与默认展示的完整含义见 查阅知识库。

规则与配置覆盖¶

下表按规则族组织，覆盖 BaziRules、TianganRules、DizhiRules、ShenshaRules 的公共带注解属性，以及 BaziSchool、BaziConfig 的字段。派生表、共享定义和独立规则不按属性数混算成一个“知识覆盖率”。

神煞¶

低层查法见 shensha_utils。表值及定义来源在 ShenshaRules，锚点取值范围与出处在 school.py 的 _ANCHOR_CHOICES，分析器接入在 analyzer/relationship.py 的 _REGISTRY。固定锚点、被查位置和原局／流运使用范围还须读注册表及消费者，不能只看表值。

当前神煞知识对象为 shensha.guoyin 与 shensha.kongwang。其余行尚无同类专门对象，不等于全库文字从未提到这些名称。源码所列古籍、现代汇编与本仓署名也不因出现在下表就成为新的 KnowledgeSource 记录。

表外计算、配置与评估边界¶

school 选择整个流派档案。其余配置和纯计算规则不能从四个规则容器的属性清单中省略。

规则族／边界

实现与配置

知识、出处与缺口

五行、干支循环

Wuxing、Ganzhi；ganzhi_of_year()、ganzhi_of_day()

五行两条本仓署名示例已存在；年／日干支计算有源码定义与基准日期，但尚无相应规则到知识来源的关联。

四柱节界与换日

Bazi；precision、day_rollover

BaziPrecision、DayRollover 与 配置与时间口径 说明边界。知识目录不是历法精度或换日出处目录。

胎元与命宫附加查询

taiyuan、minggong；纯函数在 bazi_utils

concept.taiyuan、concept.minggong 区分月柱顺移、掌诀、中气按语、本库执行政策与待核候选，均不默认展示（show_by_default=False）。三百日胎元及其他命宫月界未编码；不扩四柱、配置或旧分析，计算不认证解释。用法见 集成开发。

历法、民用钟与真太阳钟

backend；CalendarBackend、bazi/calendar/solar_time.py 与地点输入

数据来源、精度及钟的边界见 配置与时间口径 和 CalendarBackend 的说明。逐行历书／天文数据的独立定标不属本页评估；不因缺少知识条目就判计算无依据。

配偶星与配偶宫

peiou_xing_def；PeiouXingDef 与 BaziChart

已有 concept.peiou_xing、concept.peiou_gong 及带原文来源、不默认展示的条目（show_by_default=False）；历史读法、软件默认与适用条件仍须分别读取。

交运、小运、大运与流年

BaziChart；dayun_year_rule 与 DayunYearRule

顺逆、间隔折算、物理时刻线与年份标签在源码说明中；当前没有相应专门知识对象。标签规则不能代替物理边界规则。

流运查询与关系组合

transits、tiangan_utils、dizhi_utils、relationship

查询坐标、候选组合及原局／流运消费者各有语义；复用一张规则表不证明每种使用范围都有同一出处。

解释前提匹配

context_matching 与 前提判据

已有可发现判据目录与知识引用；不等同于全库计算规则的来源索引，更不自动证明解释前提成立。

国印关联示例¶

两条国印知识已经存在，不需要再次录入。默认过滤与来源访问的通用用法见 查阅知识库。这里补上当前流派字段到条目、再到来源的查阅路径。

下面的定义成员与条目 ID 对应是文档中的设计例子，不是库提供的规则关联接口。 源码规则层不依赖 KnowledgeBase。

from bazi.defines import Tiangan
from bazi.knowledge import KnowledgeBase
from bazi.rules import BaziRules, ShenshaRules
from bazi.school import BaziSchool

kb = KnowledgeBase.load()
assert {obj.object_id for obj in kb.objects.values() if obj.kind == 'shensha'} == {'shensha.guoyin', 'shensha.kongwang'}
claims = {
  ShenshaRules.GuoyinDef.MODERN: 'shensha.guoyin.modern',
  ShenshaRules.GuoyinDef.WUXING_JINGJI: 'shensha.guoyin.wuxing_jingji',
}
for definition, claim_id in claims.items():
  school = BaziSchool(guoyin_def=definition)
  entry = kb.entry(claim_id)
  table = ShenshaRules.GUOYIN[school.guoyin_def]
  target = table[Tiangan.甲]
  offset = (target.index - BaziRules.TIANGAN_LU[Tiangan.甲].index) % 12
  assert all((table[tg].index - lu.index) % 12 == offset
             for tg, lu in BaziRules.TIANGAN_LU.items())
  # 对账当前条目措辞，不把解释文字当作结构化接口。
  assert f'偏移 +{offset}' in entry.text
  assert entry.limits
  source = kb.sources[entry.sources[0]]
  print(definition.name, school.guoyin_anchor.name, '甲见' + str(target))
  print(entry.claim_id, entry.source_state, entry.show_by_default)
  print(source.source_id, source.text_layer, source.state)

这段代码只查表与知识，不创建命盘，也不执行“以哪柱查哪些位置”的命盘求值。三层支持要分别读：

层

当前事实从哪里取

来源边界

表值

ShenshaRules.GUOYIN、GuoyinDef 及条目文字

两表从禄位派生；定义说明区分原文、今人注释、抄本与现代读法，不合成一份无分歧的古籍证明。

锚点

BaziSchool.guoyin_anchor 与 _ANCHOR_CHOICES 的对应注释

支持年锚、年日双锚；年干锚的明文出自今人注释，抄本表值见证不能证明该锚。

查找位置

定义 docstring、条目 limits 与实际消费者

果老文献的身命宫不等于四柱地支；本库四柱查法的现代来源与表值来源分开。

repository_guoyin_variants 概述的是本仓说明，supports 及 limitations 都应保留阅读。该来源引用固定的仓内快照；当前表与条目对账成功，不会把历史快照变成新增的古籍见证。

关联如何维护¶

  • 计算表仍归 rules.py，默认与允许的配置归 school.py，知识文字、来源及状态归 KnowledgeBase 的注册表。禄神共表、金舆／国印派生等已有共享关系继续从源码取值，不在知识库或本页复制十格表。

  • 不能从算法派生的原文、解释、锚点依据与支持限度继续独立保留。规则或文字变更时，对照条目 ID、定义成员、实际表值、锚点范围和消费者检查差异；上面的示例只校验当前两读的偏移与文字一致，不声称已自动维护全部语义。

  • 覆盖表漏掉规则属性或配置字段，由文档测试的集合核对报告；引用与示例由严格构建及文档示例检查验证。这些检查不裁定命理依据，也不证明表外计算已经穷尽。

  • 若将来增加可查询关联，建议先在知识侧验证一组“定义成员／配置字段 → 稳定条目 ID”的窄关联，保留表值、锚点、查找位置各自的支持来源。规则层不反向导入知识层，不把本页的手写对应直接宣布为公开接口。
